## 3. D1下载契约

### 3.1 身份、入队和持久化

下载项使用账号＋可信远端卷ID＋文件版本身份，不使用行号、标题或签名URL。保存白名单DTO：原名、源身份、系列、已知文件大小/类型及队列状态；不存Cookie、密码、签名地址、worker句柄、资源token或回调。按账号隔离，切换账号暂停旧队列，终止/等待旧worker后才允许新账号提交文件。

批量add返回added/duplicate/downloaded/invalid分类计数；已经存在的文件跳过，活动/等待任务不重复入队，失败/取消项只能显式retry，防止无提示重复下载。未知大小不能假装为0字节，预览单独统计并要求确认。执行期间再次复核磁盘及路径，确认不能替代提交时复核。

队列快照原子保存，保存失败不启动worker；启动前先持久化preparing，提交后漏存完成状态由真实文件校验对账。加载损坏/伪造ID/稀疏数组/非有限计数时拒绝，不改写旧快照。重启运行项标记interrupted，队列保持暂停，用户显式继续或重试。

### 3.2 状态和控制

```text
pending -> preparing -> downloading -> validating -> completed
                         |                 |
                         +-------> failed / cancelled / interrupted
failed / cancelled / interrupted --显式重试--> pending
```

暂停只阻止下一项，不中止正在进行的一项；取消等待项立即持久化，取消运行项保持资源许可直到worker退出确认。资源占用串行，旧done/progress不得修改已结束任务或释放新token。取消到达原子提交之后，真实提交结果优先，不把已保存文件标成取消。

UI关闭不销毁队列，KOReader关闭不承诺后台下载。重试从头下载并保留安全归属的.part直到明确启动；没有服务端Range证据不宣称断点续传。弱网自动重试最多2次，仅明确可重试网络错误；401/403、损坏EPUB、路径冲突、账号变化和磁盘不足不盲重试。

### 3.3 worker与提交

沿用已验证的独立进程模式，UI只读有界进度/状态和调度，不在scheduleIn里执行HTTP。执行时解析签名；短期地址只在内存，跨项复用明确有效的索引，到期重新解析，不猜分页协议。进度有限且单调，未知总量保持未知，日志只保存枚举化错误代码与清理后的提示。

只写已归属、无链接逃逸的同目录.part；不自动覆盖已存在EPUB或外部写入结果。下载结束必须校验ZIP结构、必要EPUB资源、CRC/截断和声明大小（有可信大小时），同步临时输出后由主进程复核账号/文件身份/占用并原子提交。下载完成不触发去彩纹。最终汇总完成/失败/跳过及实际字节，一批只显示批次结果，不逐卷弹窗。

## 4. P1处理管理与质量

管理页复用现有网格、选择模型和封面组件，不另做视觉系统。按本地实际文件显示未处理/已处理/失败/处理中，系列和状态筛选不丢选择；批量确认列实际文件数、已优化跳过数、无备份覆盖后果和额外临时空间估计。执行前重新检查源指纹/占用，逐项失败继续，批次汇总，不改下载状态。

profile明确原尺寸或目标尺寸、缩放/滤波顺序、强度、算法版本；目标尺度选择需真实Colorsoft比较才能决定默认，不预先假定越小越好。身份变化不能复用旧结果。当前已优化文件不叠加处理，重新处理需重新下载原文件，不新增恢复原版入口。

## 5. 迁移、兼容与发行

schema v4迁移先备份设置元数据（不是漫画原版），验证新数据并原子替换；失败保留旧设置、目录和下载记录。未知新版本拒绝降级写入。覆盖安装不带任何运行数据。Next清单及发行源指向用户派生仓库，不能被上游版本号误覆盖；包更新失败可回退插件代码/配置，不承诺恢复无备份处理后的漫画。

UI验收覆盖600×800、758×1024及其横屏、普通/大字号、长中英文名、空/加载/错误/搜索/多选；不用改变已确认UI来绕过功能缺口。双插件先后启动、扫描、阅读后返回和关闭必须验证资源释放。真实账号只读脚本保持Git忽略，仅脱敏统计入报告。

设备门槛：需要准确KOReader版本、Colorsoft架构/动态加载证据和授权真实漫画。无法取得时标记“待设备验收”，代码TDD可继续但不能发行或声称彩纹质量达标。A/B/C比较保留原始测试样本在忽略目录：A关闭Derainbowify，B开启，C处理后关闭；即使产品不保存原版，也不能失去对照输入。性能阈值先记录同设备基线，再固定比较门槛，不能编造通用数字。

### D1.2b后端检查点
