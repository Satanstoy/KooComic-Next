# 第一阶段实施与验证记录

日期：2026-10-12；基线：`71e9f0a`；开发分支：`codex/catalog-foundation`。

## 实现范围

目录归一化、系列索引与原子快照是可独立调用的模块，尚未取代现有书库控制器。已接入当前单本工作流的是历史路径识别与打开，以及只读书库探测菜单。默认书名仍来自 `vol_name`，现有命名与文件路径不自动改变，冲突目标拒绝覆盖。

目录模型默认不信任卷 ID 或系列 ID 的跨版本稳定性；调用者只有拿到验证证据后才能开启 `volume_id_verified` / `series_id_verified`。缺少作者和可信系列 ID 时保持未分类。快照仅接受完整且显式验证的结果；本阶段没有把任何真实服务端能力标记为已验证。

## 真实服务端探测

已在用户授权的真实认证会话中执行只读请求，测试 `limit=28/50/100/200/500/1000/2000`，确认扩大 limit 能获取旧客户端遗漏的记录，并观测到 `total` 字段。测试结果区别于模拟响应测试；当前账号书库数量较小，不能据此宣称服务端的全局上限或更大目录的完整枚举已验证。

独立 HTTP 脚本与测试、账号级统计报告只保存在本机 `.local/koobone-probe/`，由 `.git/info/exclude` 排除。密码隐藏输入且仅用于进程内登录，会话只保存在内存 CookieJar；不保存原始响应、书名或签名地址。报告仅包含返回数量、去重数量、交集和耗时等汇总，不将私人书库信息提交到公开仓库。

## 真机待验证

1. 在 KOReader 安装开发分支构建的插件，先备份用户设置，保留原漫画文件，不更改下载目录。
2. 登录自己的 KOOBONE 账号，选择“工具 → koo漫画 → 书库能力探测（只读）”，记录 28/50/100 的返回数量和新增数量；只分享此汇总，不分享密码、Cookie、签名 URL 或完整书库内容。
3. 如果 100 的请求发现更多记录，仅证明 limit 有增量；仍需观察真实网页客户端及服务端终止机制，验证完整枚举。菜单探测本身不能解除发布门槛。
4. 对旧下载记录路径仍存在、云端书名改变的漫画，检查书架状态和“打开阅读”都使用原文件；通过外部文件管理删除后应显示未下载。
5. 测试正常单本下载、重试旧路径和同名冲突拒绝；确认不会改变默认书名或覆盖其他卷。此步骤的真实传输尚未在本环境执行。

当前仍使用上游更新渠道，不创建派生版 release 或版本标签。完整同步、系列 UI、离线启动、schema v4、队列、批量删除和 Colorsoft 性能需要后续阶段实施与验证。
